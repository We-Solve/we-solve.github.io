Depth-Independent Attribute-Based Encryption

Definitions and mathematical statement

Shared notation.
Standard number systems are $\mathbb N,\mathbb Z,\mathbb Q,\mathbb R,\mathbb C$. Specialized notation and index ranges follow the cited source and the definitions below.

Attribute-based encryption associates ciphertexts or keys with attributes and access policies, permitting decryption when the policy is satisfied. Circuit depth is the longest gate path in the represented policy; key-homomorphic encryption supports prescribed algebraic combinations of keys.

Translation functionality alone does not establish an application

The source's fully key-homomorphic encryption translates a ciphertext under attribute vector $x$ into one decryptable under the derived key label $(f(x),f)$, preserving its message. This is not merely additive homomorphism of ordinary encryption keys. We test the proposed route from that functionality to key-policy attribute-based encryption.
Proposition: Assume a translation scheme has correctness for every allowed function $f$. Giving a policy holder the secret key for label $(1,f)$ allows correct decryption of a ciphertext under $x$ whenever $f(x)=1$, by first translating it using $f$. However, these correctness statements alone do not imply secrecy of the resulting system.
Proof: On an encryption of $m$ under $x$, the translation correctness hypothesis says that applying the public operation for $f$ yields a ciphertext decryptable with the key labeled $(f(x),f)$ and returns $m$. If $f(x)=1$, this is exactly the supplied policy key, proving the conditional correctness statement. For the second assertion, consider the deliberately insecure syntax $\operatorname{Enc}(x,m)=(x,m)$ and $T_f(x,m)=(f(x),f,m)$. Let keys be their public labels; decryption returns the embedded message when labels match and $\bot$ otherwise. This syntax satisfies the displayed functional translation and decryption requirements perfectly. Yet an observer reads $m$ directly from the initial or translated ciphertext, without any key. Thus functional correctness cannot by itself entail message secrecy or an attribute-based-encryption security game. ∎
The counterexample is not claimed to satisfy the source's security definition, compactness requirements, or computational assumptions; violating secrecy is its purpose. The source already derives applications using security as well as functionality. The failed attempted inference here is dropping that security premise when transferring an application from the translation identity alone.

Verification and remaining gaps

For two-bit attributes, three simple Boolean policies and both one-bit messages, every satisfied-policy translation was checked to decrypt correctly in the toy syntax, while direct reading recovers every message. This finite enumeration verifies the separation of correctness from confidentiality; it provides no secure primitive.
