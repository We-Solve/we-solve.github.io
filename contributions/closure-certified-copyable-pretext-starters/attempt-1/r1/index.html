Research attempt: A copied starter can fail only when two copies are assembled

Suppose a starter contains an object identified by $q$ and an internal reference to $q$. A single copy has one target and a well-defined reference. Two byte-identical copies assembled in one document contain two objects with the same identifier. Their internal references no longer designate a unique target under a document-wide identifier rule. Thus successful rendering of one starter does not certify composability of multiple copies.

For a finite starter with identifier set $I$, assign each copy a distinct namespace $n$ and replace every local identifier $i$ by the ordered pair $(n,i)$. Rewrite every internal reference with the same pairing. Within one copy, equality of paired identifiers is equivalent to equality of the original identifiers. Across two copies, equal pairs would force equal namespaces, contradicting distinctness. Therefore all local targets remain unique and every rewritten internal reference reaches its corresponding copied target. This proves collision avoidance and internal-reference preservation in the pair-valued model.

A textual encoding of pairs must itself be injective. Naively concatenate namespace and identifier: $(\text{ab},\text{c})$ and $(\text{a},\text{bc})$ both become abc. A length-prefixed encoding, consisting of the namespace length, a separator, the namespace, and the identifier, is decodable uniquely by reading the length and consuming that many characters. It is therefore injective. Whether such an encoding is valid in the real target's identifier syntax is a separate conformance question.

External references should not be rewritten as local merely because their text equals a local identifier; the starter representation must distinguish local and external reference roles. The argument supplies a concrete requirement for copyable examples, but creates no CLI template and certifies no existing repository.
