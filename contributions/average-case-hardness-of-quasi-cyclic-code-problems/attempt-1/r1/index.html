Definitions and mathematical statement

Shared notation.
Standard number systems are denoted by $\mathbb N,\mathbb Z,\mathbb Q,\mathbb R,\mathbb C$; index ranges, computational models and specialized notation follow the cited problem source and the definitions below.

An element of $R_p$ is represented by a binary polynomial modulo $x^p-1$. Its Hamming weight counts nonzero coefficients; total weight sums the weights of the two displayed polynomial components.

A code $C\subseteq\Sigma^N$ is a set of permitted length-$N$ words. Its Hamming minimum distance is the minimum number of unequal coordinates of two distinct words. For a linear $[N,K,D]_q$ code, rate is $K/N$ and relative distance is $D/N$; decoding recovers a codeword from corrupted observations.

Statement recorded in the supplied source.
Let $R_p=\mathbb F_2[x]/(x^p-1)$. Extend average-case decoding-hardness results to quasi-cyclic codes, and prove a polynomial equivalence between the following problems: finding $e_0,e_1\in R_p$ of bounded total Hamming weight with $e_0+e_1h=s$, and deciding whether there exist nonzero $h_0,h_1\in R_p$ of bounded total Hamming weight with $h_0+h_1h=0$. [S2]

Research attempt: Coset decoding and a failed quasi-cyclic homogenization

The two geometric tasks.
In $R_p=\mathbb F_2[x]/(x^p-1)$ define \[ C_h=\{(uh,u):u\in R_p\}\subseteq\mathbb F_2^{2p}. \] This is a binary linear code of dimension $p$, since the second coordinate recovers $u$. It is invariant under simultaneous cyclic shifts because multiplication by $x$ commutes with multiplication by $h$. Every solution of $e_0+e_1h=s$ is uniquely \[ (e_0,e_1)=(s+uh,u),\qquad u=e_1. \] Thus decoding asks whether the affine coset $(s,0)+C_h$ contains a vector of weight at most $t$, whereas the codeword question concerns low-weight vectors of $C_h$ with both coordinates nonzero. If $h$ is a unit, any nonzero $u$ has $uh\ne0$, so the latter is the ordinary nonzero minimum-distance question. For general $h$ that extra condition matters: at $h=0$, Problem 3 is always negative, while decoding reduces to testing $|s|\le t$, by choosing $u=0$ and noting that $|s|+|u|$ cannot be smaller than $|s|$.

A direct exact decoding algorithm enumerates $u$ of weight at most $t$, computes $s+uh$, and checks the total weight. This is complete because any feasible solution has $|u|\le t$. Naive cyclic multiplication costs $O(p^2)$ bit operations, giving \[ O\left(p^2\sum_{j=0}^{\min(t,p)}\binom pj\right) \] up to comparable weight-checking work. For fixed $t$ this is polynomial; for growing weights it gives no uniform polynomial algorithm. The codeword problem has the analogous enumeration with the two nonzero checks. This does not establish average-case hardness or an equivalence.

Ordinary homogenization already needs a promise.
Adjoin $(s,0)$ to the binary linear span of $C_h$, obtaining \[ C'=C_h\cup\left((s,0)+C_h\right) \] when $(s,0)\notin C_h$. A short nonzero vector in $C'$ might already lie in $C_h$, unrelated to the desired syndrome. Only a promise that the old code has minimum distance greater than $t$ removes this false positive. Moreover the dimension usually becomes $p+1$, outside the original systematic dimension-$p$ family. Closing under cyclic shifts creates a further obstruction, even when the old-distance promise holds.
An explicit failure after cyclic closure.
Take $p=5$, $h=1$, $s=1+x+x^2$, and $t=1$. The old code is $C_1=\{(u,u)\}$, whose nonzero vectors have weight at least two. The decoding instance is negative because \[ |e_0|+|e_1|\ge |e_0+e_1|=|s|=3. \] Here the inequality holds coefficientwise: a nonzero coefficient of the sum requires at least one nonzero summand coefficient.

But in $R_5$ one has \[ (x+x^2+x^4)(1+x+x^2)=1. \] Expansion in $\mathbb F_2[x]$ gives $x+x^5+x^6$, since each of $x^2,x^3,x^4$ occurs twice. Reduction by $x^5=1$ and $x^6=x$ gives $1$. Therefore the smallest cyclic submodule containing $(s,0)$ contains $(1,0)$, of weight one. Adding it to $C_1$ and using $(1,1)\in C_1$ also gives $(0,1)$, so the cyclic closure is actually all of $R_5^2$. A procedure that homogenizes by adjoining all cyclic shifts would turn this negative decoding instance into a code with trivial low-weight words and would leave the original code family. The weight-one vectors $(1,0)$ and $(0,1)$ do not satisfy Problem 3's requirement that both components be nonzero. Thus the example is a false positive for ordinary minimum-distance homogenization and a departure from the original family, not a positive instance of original Problem 3 at weight one.

This counterexample defeats that particular reduction. It does not show that no more elaborate polynomial reduction between the source problems exists; such a reduction would need to preserve the family, its nonzero-component convention, the weight thresholds and the intended average-case distributions.

Verification and adversarial audit

The code dimension, affine-coset parametrization, unit versus nonunit boundary and exhaustive-search completeness were checked directly. The five-bit inverse was computed by enumerating all $32$ ring elements with exact cyclic binary multiplication; the unique inverse had exponent set $\{1,2,4\}$. The no-decoding-at-weight-one conclusion follows independently from the weight inequality. The distinction between an arbitrary nonzero codeword and both components nonzero is retained.

Scope and remaining gaps

The original average-case hardness statement and polynomial equivalence remain unproved. The attempted homogenization fails before distributional issues even arise: it admits old-code words, can change dimension, and its cyclic closure can introduce spurious very short vectors. A family- and distribution-preserving reduction with controlled weights is the first missing step.
