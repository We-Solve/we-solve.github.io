A concrete dependency-selection calculation

The source asks how to turn intentions into actions. We test a restricted planning component after people have supplied a finite list of possible actions, signed utility weights $w_i$, and prerequisites. Selecting action $i$ requires selecting every prerequisite $j$ listed by an arc $i\to j$. A selected set satisfying these implications is called closed. There is no separate budget constraint in this model, and weights are assumed additive.
Proposition: A maximum-weight closed set can be obtained from a minimum source-to-sink cut in the following capacitated network. For $w_i>0$ add $s\to i$ of capacity $w_i$; for $w_i<0$ add $i\to t$ of capacity $-w_i$; for each prerequisite arc add capacity $M>\sum_i|w_i|$.
Proof: For any cut with $s$ on its source side, let $S$ be the action vertices on that side. Selecting no actions gives a cut of capacity $C_+=\sum_{w_i>0}w_i<M$. Hence a minimum cut has capacity less than $M$ and crosses no prerequisite arc. Thus if $i\in S$ and $i\to j$, then $j\in S$, so $S$ is closed. Conversely a closed set yields no prerequisite crossing and has cut capacity \[ \sum_{i\notin S,w_i>0}w_i+\sum_{i\in S,w_i<0}(-w_i) =C_+-\sum_{i\in S}w_i. \] Minimizing this expression is exactly maximizing the closed-set weight. A minimum exists because the finite network has finitely many cuts; the reduction does not require an unproved claim about a particular flow implementation. ∎
As a worked example, action $a$ has weight 8 and requires setup $b$ of weight $-3$; action $c$ has weight 2 and requires $d$ of weight $-5$. The best closed set is $\{a,b\}$ with weight 5; including the second pair reduces it to 2. With $M=19$, exhaustive cuts reproduce this choice and minimum capacity $10-5=5$.
