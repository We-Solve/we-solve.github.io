Verbatim supplied catalogue question

Does unrelated graph balancing admit an approximation factor below $2$, even for simple graphs in which every orientation-dependent edge weight belongs to $\{1,k\}$ for a fixed $k$?

The natural load-assignment route

The source allows different processing times at the two endpoints, including the restricted set $\{1,k\}$. We give a complete unit-load feasibility algorithm and then test the tempting extension of simply choosing each cheaper endpoint. The latter fails arbitrarily badly even for a fixed $k$ on simple graphs.
Unit loads reduce exactly to matching.
Suppose every allowed endpoint assignment has load one, and ask whether maximum load at most an integer $B\ge0$ is possible. Create one job node for each edge, and $B$ slot nodes for each graph vertex. Join a job to every slot of each endpoint to which it is allowed to be assigned. A matching covering all job nodes is equivalent to a feasible orientation: a matched slot chooses the endpoint and distinct slots ensure at most $B$ jobs there. Conversely assign distinct local slots to the jobs of every feasible orientation. The graph has at most $|V|B+|E|$ nodes. One never needs $B>|E|$, because assigning all edges arbitrarily uses no more than $|E|$ jobs at any vertex.

For completeness, a covering matching can be found or its absence certified by augmenting paths. Start with the empty matching. Search from an unmatched job, alternating unused job-slot edges and matched slot-job edges. If a free slot is reached, reverse membership of the path edges, increasing the matching by one. If no unmatched job has such a path but a larger matching existed, the symmetric difference of the two matchings would have components that are alternating paths or cycles (each vertex has degree at most two). Since the larger matching has more edges, one path has one more edge of it than of the current matching; it begins and ends at vertices unmatched by the current matching, giving an augmenting path. This contradiction proves maximal size and correctness. There are at most $|E|$ augmentations and each search scans a polynomial-size graph, so the algorithm is polynomial. Binary search over $B=0,\ldots,|E|$ gives the exact unit-load optimum.

A valid restricted extension below the heavy-job threshold.
For processing times in $\{1,k\}$, any proposed makespan $B<k$ forbids assigning an edge to an endpoint where it takes time $k$. Delete those choices and apply the preceding unit-load test with capacity $\lfloor B\rfloor$. This is an exact feasibility procedure for this threshold range. It does not address the general regime $B\ge k$, where heavy assignments can occur and consume $k$ units of capacity rather than one slot.
Choosing every cheap endpoint has unbounded ratio.
Fix an integer $k\ge2$ and take a star with $t\ge k$ leaves. Each edge takes time one at the center and time $k$ at its own leaf. The graph is simple and all processing times are in the prescribed two-value set. Choosing the cheaper endpoint for each edge assigns all $t$ jobs to the center, with makespan $t$. Assigning every edge to its leaf gives makespan $k$. No solution has makespan below $k$: if any edge goes to a leaf it alone creates load $k$, while if none does the center has load $t\ge k$. Thus the optimum is exactly $k$ and the cheap-endpoint ratio is $t/k$, unbounded with $t$ even though $k$ is fixed.

The same example explains why minimizing total processing time is not a substitute for minimizing maximum load. The unique minimum total-time assignment uses all cheap center endpoints and has total $t$, yet the balanced solution with maximum load $k$ has total $kt$. Total-time optimality contains no constant-factor makespan conclusion here.
