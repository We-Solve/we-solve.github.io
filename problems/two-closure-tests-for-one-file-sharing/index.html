Research attempt: One physical file versus closure of required resources

Let a delivered artifact have a finite dependency graph, rooted at its main document. A resource edge means that displaying a required feature needs the target resource. A file count of one does not imply offline completeness: one HTML file can refer to a stylesheet $c$ which in turn requires a font $f$, with neither embedded. The main document alone has one file but lacks the reachable resources $c,f$. Conversely an archive with three files can contain the entire dependency graph and be complete under the model.

Given an explicit finite graph and a set $L$ of locally available resources, offline closure is exactly the condition that every vertex reachable from the root lies in $L$. Necessity follows because a missing reachable vertex occurs at the end of a dependency path for a required feature. Sufficiency follows by induction on resource traversal: each requested dependency is reachable and therefore locally available. This sufficiency assumes that the graph lists every request and that the runtime can consume the local representation; it says nothing about browser policy or disabled scripts. A graph search checks the condition in linear time in the explicit graph.

A static scan can miss dependencies if the model permits computed requests. A program that constructs a URL from an arbitrary learner input has infinitely many possible resource names when inputs are unrestricted. No finite embedded set can contain all distinct required resources in that model. For a finite declared input set, one can enumerate the corresponding requests; without such a restriction, packaging a finite set does not prove universal offline behavior. Thus both resource enumeration and actual runtime capabilities are separate premises behind a single-file sharing claim.
