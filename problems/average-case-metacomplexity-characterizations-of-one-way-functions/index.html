Our mathematical attempt checks a tempting route from counting incompressible strings to the claimed cryptographic hardness; the route fails for an explicit reason.

Counting short descriptions gives an easy classifier

Fix a universal description machine and let $K(x)$ be plain Kolmogorov complexity. There are $2^L-1$ binary programs of length less than $L$, so at most that many distinct strings have $K(x)<L$. For a uniform $n$-bit string and an integer $c$ with $0\le c\le n$, \[ \Pr\{K(x)<n-c\}\le\frac{2^{n-c}-1}{2^n}<2^{-c}. \] The same upper count applies to any time-bounded complexity, because restricting running times can only decrease the number of outputs of the short programs. Thus the constant algorithm that always predicts $K(x)\ge n-c$ decides this particular threshold predicate with error less than $2^{-c}$ under the uniform distribution. For $c=\lceil3\log_2n\rceil\le n$, its error is less than $n^{-3}$.

This does not make exact complexity easy, and does not refute a carefully specified gap problem or sampler-based characterization. It shows the precise failure of the attempted inference: "most strings need long descriptions" is a counting statement, whereas a balanced or suitably distributed decision task may require distinguishing rare structured strings. Counting alone can instead make an unbalanced decision problem easy on average.

The same obstruction for truth-table circuit complexity

Consider a Boolean function on $m$ inputs, supplied by its $N=2^m$-bit truth table. Count fan-in-two circuits with at most $s\ge1$ gates over the sixteen binary Boolean operations. Topologically order their gates. Each gate chooses its operation and two predecessors among at most $m+s$ wires; the output chooses one of those wires. Summing over gate counts at most $s$ bounds the number of descriptions by \[ (s+1)(m+s)\left(16(m+s)^2\right)^s. \] Unused inputs and redundant descriptions only overcount functions, which is harmless. Therefore a uniformly random truth table has minimum circuit size at most $s$ with probability at most this quantity divided by $2^N$. In regimes where its base-two logarithm is at most $N/2$, always answering "size exceeds $s$" has error at most $2^{-N/2}$. Again a large typical circuit size is not by itself average-case hardness of this threshold decision task. This elementary counting argument does not prove or disprove the source's gap-MCSP equivalence.

Uncomputability and bounded time are distinct

For completeness, exact unbounded $K$ is not computable. If it were, for each $n$ choose the lexicographically first $n$-bit string $x_n$ with $K(x_n)\ge n$; the short-program count guarantees its existence, and computable $K$ would make this search an algorithm. An algorithm containing a self-delimiting encoding of $n$ followed by this fixed search program would print $x_n$ using $2\lfloor\log_2n\rfloor+O(1)$ bits: encode the binary length in unary and then the binary expansion. For sufficiently large $n$ this is less than $n$, a contradiction. The fixed program's simulation overhead changes only the constant in plain description length.

By contrast, fix a computable time bound $t(n)$ large enough for literal printing in the chosen machine. There is a constant $c_0$ such that every $n$-bit string has a literal program of length at most $n+c_0$ within this bound. Enumerate all programs of length at most $n+c_0$, simulate each for $t(n)$ steps, and select the shortest producing $x$. This finite procedure computes $K^t(x)$ exactly. Its enumeration is exponential in $n$; decidability is not a polynomial-time algorithm. If a time bound does not allow the literal-printing premise, that premise must be replaced by an explicit finite search convention, rather than being silently assumed.
