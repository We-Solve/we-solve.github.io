Research attempt: A static fallback may preserve one data task and lose another

Take an embedded data object consisting of an ordered pair $(x_1,x_2)$. A static fallback showing only the unordered multiset of the two values preserves tasks that depend only on that multiset, such as their sum. It fails the task of identifying which index has the larger value: inputs $(0,1)$ and $(1,0)$ produce the same multiset but have different maximizing indices. Any answer computed only from that fallback must be the same for both and hence cannot be correct on both.

For the specific maximum-location task on pairs with unequal entries, a different fallback can store $(i_*,x_{i_*})$, where $i_*$ is the unique maximizing index. A decoder returning the stored index and value answers that task exactly. But this fallback loses arbitrary entry queries. Inputs $(0,2)$ and $(1,2)$ have the same maximum summary $(2,2)$, while the first entries differ. Thus success on one declared task does not imply preservation of the whole embedded object or all interactive queries.

The general finite statement is simple but useful. For a representation map $F:X\to Y$ and task $q:X\to Z$, a decoder $d$ with $q=d\circ F$ exists exactly when $q$ is constant on every fiber of $F$. Necessity follows because equal $F$ values give equal decoder outputs. For sufficiency, define $d(y)$ to be $q(x)$ for any $x$ with $F(x)=y$; fiber constancy makes this well-defined on the image. Values outside the image can be left undefined. The two examples respectively satisfy and violate this condition for different tasks.

This supplies an exact test of claimed fallback semantics in a finite model. It does not equate diagrams, proof tools, audio, and datasets, nor determine accessibility or embedding APIs for the systems named in the source.
